## What is native / adapter / external / unavailable
- **Native**: instruction files, agent files (Claude, Copilot), hooks, Claude statusline metrics.
- **Adapter** (generated by `mesh sync`): `AGENTS.md` managed block, `CLAUDE.md` import, hook configs, agent files, payload normalisation per CLI.
- **External** (the mesh itself): tasks, dependencies, locks, bus, memory, checkpoints, worktrees, integration, dashboard, `mesh run` wrapper (gives Antigravity the SessionEnd it lacks).
- **Estimated**: context % for CLIs without metrics (transcript bytes/4, labelled `estimated`; only used if `mesh usage record --transcript` is called — no automatic collector exists for Antigravity/Copilot).
- **Unavailable (never fabricated)**: Antigravity/Copilot token counts and quota; Copilot context %.

## Known risks / unverified
1. Copilot loads `.claude/settings.json` hooks as well as `.github/hooks/mesh.json`: both may fire for one Copilot session (Claude-style payload registering a `claude-…` session). Handlers are idempotent, but session attribution may be wrong. Verify live.
2. Copilot `toolArgs` shape and Antigravity edit-tool argument names are matched heuristically (`path`, `file_path`, `TargetFile`, …). A tool using other names would bypass the lock check; worktree isolation + `mesh integrate` conflict detection remain the backstop.
3. Antigravity `injectSteps` wrapper structure follows the doc example; not live-tested.
4. Antigravity legacy `.agents/workflows/` reportedly stopped working 2026-10-19 (third-party); not used here.
5. Hook enforcement is advisory against a determined agent (it could run shell commands that modify files); it prevents accidents, not adversaries.

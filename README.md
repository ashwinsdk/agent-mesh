# agent-mesh

Turns any git repository into a coordinated multi-agent workspace for **Claude Code, Antigravity (`agy`) and GitHub Copilot CLI** (and anything that can read `AGENTS.md` / run shell commands). Shared tasks, memory, messages, file locks, checkpoints and honest usage tracking live in the repo (`.mesh/`), not in any CLI's chat history. Python 3.11+ stdlib only; macOS/Linux.

## Install the tool once (any machine)
```sh
brew install pipx && pipx ensurepath        # once, if you don't have pipx
pipx install git+https://github.com/ashwinsdk/agent-mesh.git
```
Other forms:
```sh
pipx install git+https://github.com/ashwinsdk/agent-mesh.git          # latest
pipx install git+https://github.com/ashwinsdk/agent-mesh.git@v0.1.0   # pinned release
pipx upgrade agent-mesh                                              # later
```
This gives you a global `mesh` command (needs Python 3.11+; `pip install` works too). Then in any repo: `mesh init`.

## Install into a project
```sh
mesh init        # in the target repo; or: /path/to/agent-mesh/install.sh /path/to/repo
.mesh/bin/mesh doctor                    # capability matrix, integrity, installed clients
git add .mesh AGENTS.md CLAUDE.md .claude .github .agents .gitignore
```
`init` detects the stack (npm, pyproject, cargo, go, …), writes `.mesh/mesh.toml`, vendors the tool into `.mesh/lib` (the repo is self-contained), installs 14 agent roles, and generates client config. Existing `CLAUDE.md`/`AGENTS.md`/`.claude/settings.json`/agent files are merged or skipped, never overwritten; hand-edited managed blocks produce `*.mesh-proposed` instead.

## Starting a new project: default prompts
There is no built-in prompt; `AGENTS.md` (generated by `init`) is the standing instruction every CLI loads. Use the prompts below to kick things off. They work in Claude Code, Copilot CLI and Antigravity alike; replace the bracketed parts.

Set up a fresh project (keep the tool outside it):
```sh
mkdir my-project && cd my-project && git init -b main
echo "# my-project" > README.md && git add -A && git commit -m init
/path/to/agent-mesh/bin/mesh init && .mesh/bin/mesh doctor && git add -A && git commit -m "add mesh"
```

**1. Orchestrator prompt** (one session; paste first):
```
You are the orchestrator for a multi-agent build. Read AGENTS.md first.

Goal: [describe the product, stack and constraints].

Do NOT write code yet. First:
1. Use `.mesh/bin/mesh task create` to make one epic and subtasks, each with --files ownership
   and --dep where order matters. Keep independent areas in separate files so they can run in parallel.
2. Set [validation].test in .mesh/mesh.toml to [your build/test command] and tell me the change.
3. Show `.mesh/bin/mesh task tree` and wait for my approval.
Use the fewest agents that make sense; simple work needs one.
```

**2. Worker prompt** (each additional terminal/CLI, after you approve the plan):
```
Read AGENTS.md. Run `.mesh/bin/mesh task ready`, claim one task that fits your role with
`.mesh/bin/mesh task claim <id> --as <your session id>`, work only in its worktree and files,
run `.mesh/bin/mesh checkpoint create` after each meaningful step, run the tests, then
`.mesh/bin/mesh task review <id>`. If a claim or edit is refused, pick other work or message the owner.
```

**3. Resume prompt** (after a crash, usage limit or full context; any CLI):
```
Read AGENTS.md. Run `.mesh/bin/mesh resume` to list interrupted tasks, then
`.mesh/bin/mesh task resume <id>` and `.mesh/bin/mesh resume <id>`. Verify the brief against
`git status` and `git log`, then continue from its next actions without repeating completed steps.
```

If a CLI's session id was not injected at startup, run `.mesh/bin/mesh session start --cli <claude|copilot|antigravity>` and pass `--as <id>` on every mesh command. Watch progress with `.mesh/bin/mesh dash`.

## One prompt, supervised team (v2)
```sh
mesh up claude "Build a modern 3D website for a premium water bottle brand with a backend"   # or copilot / antigravity
mesh dash                      # live tabs; `mesh dash --web` for a read-only browser view
```
The chosen CLI becomes the orchestrator (shipped playbook, nothing to paste). It plans, spawns headless worker sessions in git worktrees, supervises them event-driven, verifies their work against the real commit, and integrates it. Details, limits and the autonomy policy: [docs/ORCHESTRATION.md](docs/ORCHESTRATION.md). Check parsers against your real CLIs first: `mesh probe claude --yes`. Existing projects: `pipx install --force git+https://github.com/ashwinsdk/agent-mesh.git && mesh upgrade && mesh sync`.

## Daily use
```sh
mesh task create "Add login" --files "src/auth/**" --accept "tests pass"   # orchestrator or human
mesh task ready                         # what can start now (deps satisfied)
mesh task claim T-xxxx --as <session>   # atomic; takes file locks; fails if owned/overlapping
mesh worktree create T-xxxx             # isolated branch mesh/T-xxxx
mesh checkpoint create --done "…" --next "…" --decision "…"
mesh msg send --to cli:claude --type question "which auth header?"
mesh integrate T-xxxx                   # validate → conflict check → merge → re-validate
mesh dash                               # live TUI (q to quit); --once for plain text
mesh usage report                       # JSON; source = reported | estimated | unavailable
```
Agents get their session id and protocol automatically via SessionStart hooks and `AGENTS.md`. Launch several terminals (any mix of CLIs) in the same repo; run `mesh run <claude|copilot|antigravity> --task T-xxxx` for a wrapper that registers the session, resumes a task and checkpoints on crash/exit (useful for Antigravity, which has no SessionEnd hook).

## Recovery
- Interrupted task: `mesh resume` (lists), `mesh task resume T-xxxx`, `mesh resume T-xxxx` (brief with checkpoint + repo-drift warnings). Works from a different CLI.
- Context full: `mesh rollover [--launch copilot]`.
- Corrupt DB: `mesh doctor --repair` / `mesh restore` (uses `mesh backup` snapshots). Corrupt checkpoint: automatically falls back to the previous valid one.
- Stale locks: expire by TTL and are reclaimed when the owner session ended or its PID died; `mesh task reap` returns abandoned tasks to READY.

## Configuration (`.mesh/mesh.toml`)
`[validation].test` is what `integrate` runs (auto-detected, edit it). `[context]` thresholds, `[locks].ttl_seconds`, `[tasks].stale_after_seconds`, `[policy]` (`destructive`, `secret_in_write`, `protect_mesh_files`). Change agent roles by editing `.mesh/agents/*.md` then `mesh sync`.

## Troubleshooting
- Hooks seem inactive: `mesh doctor` ("hooks seen live here"), check `.mesh/runtime/logs/hook-errors.log`; hooks fail open by design.
- Edit denied unexpectedly: `mesh lock list`; ask the owner to release, or `mesh msg send --type file_request`.
- `mesh: not inside a mesh project`: run from within the repo or set `MESH_ROOT`.
- Customised statusline: mesh keeps yours; chain `.mesh/bin/mesh statusline` to get Claude usage/context tracking.
- Update the vendored copy after pulling a new agent-mesh: `mesh upgrade && mesh sync`.
